# Pixel Runner

摄像头体态 / 键盘三车道像素跑酷。游戏使用 Pygame CE；键盘与体态共享同一套六字段控制接口。

## 启动

在本目录运行：

```powershell
python -m pip install -r requirements.txt
python game.py --fake
```

- **键盘模式**只需要 `pygame-ce`（`numpy` 是摄像头帧的依赖）。它不需要 OpenCV、MediaPipe、Pillow，也不需要摄像头。
- **体态模式**还需要相邻 `camera_behavior_detect/` 的依赖，即 `mediapipe`、`opencv-contrib-python`、`pillow`。请先按 `camera_behavior_detect/README_CAMERA.md` 配好视觉环境，并在同一个 Python 环境安装游戏依赖。
- 视觉模块默认读取相邻目录，也可用环境变量 `MOTIONQUEST_VISION_DIR` 指定位置。找不到时游戏不会静默卡住，而是在"选择控制方式"页面显示具体原因。
- 不加 `--fake` 时先在主菜单选择键盘或体态。

## 操作

菜单与页面

- 主菜单：标题为"一起运动吧"。鼠标点击"开始游戏 / 设置 / 退出游戏"，或 Enter 进入选择控制方式，Esc 退出。
- 选择控制方式：K 选键盘、C 选体态，也可点击"返回"回到主菜单。体态启动失败的原因显示在这一页。
- 设置页面：难度（简单 / 普通 / 困难，点击循环）、减少闪烁、声音总开关、背景音乐音量、音效音量、全屏 / 窗口，以及返回。Esc 同样可以关闭设置。设置立即生效并保存到 `preferences.json`。
- 说明页：可以选择"安全练习"或"开始奔跑"，也可以返回主菜单。体态模式下这里显示摄像头画面与校准进度。
- 暂停页：继续游戏（Esc）、重新开始、设置、返回主菜单。
- 结算页：再跑一次（Enter）或返回主菜单。

奔跑

- K / C：菜单里选择键盘 / 体态。
- 左右方向键 / A D：换道；Space / W / 上方向键：跳跃。
- 下方向键 / S：按住下蹲，松开站起；窗口失焦会释放下蹲并暂停。
- O：切换张臂。张臂开始时开启护盾，20 能量、3 秒，仅免伤，不吸附金币。
- U：切换举手。举手开始时冲刺，30 能量、2 秒、1.65 倍速度并免伤。
- 技能需先结束姿势再重新做动作；持续保持不会反复扣能量。技能持续期间不叠加。
- 体态模式：身体横移换道，实际跳起 / 下蹲 / 张臂 / 双手举起；C 重新校准。
- P：体态模式下开关右上角摄像头预览（画面上已叠加实时骨骼与动作读数）；G：说明页；M：声音总开关；Esc：暂停 / 继续；F11：全屏 / 窗口；关闭窗口退出。
- 游戏结束按 Enter：清空本局分数、金币、能量变化、动作、技能、障碍和粒子后重新开始。

## 界面与反馈

- 开始与追踪恢复都有 3 秒倒计时：倒计时期间道路不移动，屏幕中央显示剩余秒数。
- 暂停、结算、设置都是带可点击按钮的面板，不再只是"画面静止"。
- 失去追踪、摄像头启动失败、找不到视觉模块都会在屏幕上给出文字原因。
- 技能开启、能量不足、设置无法保存等即时反馈显示为画面上方的提示条。
- 说明页左侧是障碍图例：红色砖墙与缺口要跳，隧道与低标牌要蹲。键盘模式在同一位置显示六字段动作模拟窗口，体态模式显示摄像头画面与校准取景框、进度条。
- 简单难度会提示前方障碍需要的动作（前方 跳跃 / 下蹲），普通与困难关闭该提示。
- 结算显示碰撞原因、距离、得分、金币、避障次数和最高分，刷新纪录时额外提示"新纪录"；体态模式还会列出本轮运动数据（见下）。

## 规则与反馈

砖墙、缺口需跳跃；隧道、低标牌需下蹲，也可换道躲避。
换道采用平滑位移，碰撞按实际位置判断。跳跃为约 0.8 秒抛物线，需达到有效高度；下蹲逐渐压缩身体。
障碍从远向近移动，道路按游戏速度滚动；跑步摆腿、落地尘土、金币粒子、护盾光圈、冲刺拖线、碰撞粒子与闪烁均已接入。
失去追踪会冻结游戏；重新入镜后自动恢复。暂停与结束会暂停背景音乐。
跳跃、金币、技能、碰撞音效和循环背景旋律由本地代码合成，无需外部音频素材；没有音频设备时可静音运行。
速度仍保留原设计：前 120 秒从 300 逐渐下降到 190；`--density 0.58` 控制障碍密度，`--difficulty easy|normal|hard` 可直接指定难度。
每满 0.8 秒恢复 1 点能量；暂停、教学和练习不积累。张臂为护盾，包含缺口免伤；举手为冲刺。
安全练习可验证换道、跳跃、下蹲、护盾和冲刺，不扣能量、不发生碰撞，右侧清单会逐项打勾。
偏好与最高分保存在本目录 `preferences.json`（不纳入版本控制）。

## 难度与关卡设计

障碍按"波次"生成，一波可以是单点、双道、三道全封、斜向连续、同车道连续或跳蹲连招。
所有障碍仍然从 z=0 生成，因此透视和反应时间保持一致；波次只决定每件障碍与金币的出现时机。

| 难度 | 速度倍率 | 波次间隔 | 关卡特点 |
| --- | --- | --- | --- |
| 简单 | 0.80 | 2.4–3.4 秒 | 单点障碍与金币引导为主，偶发双道；提示前方动作 |
| 普通 | 1.00 | 1.7–2.5 秒 | 加入斜向连续（S 形走位）、同车道连续、跳蹲连招 |
| 困难 | 1.25 | 1.15–1.8 秒 | 三道全封、双动作混合道、连招密集，几乎没有喘息 |

关卡模式（`level.py` 中的 `PATTERNS`）：

| 名称 | 形状 | 设计意图 |
| --- | --- | --- |
| `single` | 单条道一个障碍 | 基础节奏；六成概率在别的道铺金币 |
| `pair` | 两条道同动作封死 | 留一条安全道，可用动作硬过，也可以换道 |
| `split` | 两条道分别要跳和蹲 | 必须看清自己所在道的动作，或换到空道 |
| `corridor` | 一条道障碍 + 金币铺路 | 金币提前铺在安全道上，引导玩家换道 |
| `slalom` | 三条道依次各来一个 | 走出 S 形路线，金币沿路线摆放 |
| `gauntlet` | 同一条道连续三个 | 固定节奏的跳跃或下蹲，障碍正上方有金币 |
| `combo` | 同一条道先跳后蹲（或反之） | 间隔 1.25 秒，考验动作切换 |
| `wave3` | 三道同时封死 | **无法靠左右移动躲避**，只能跳或只能蹲 |

金币与障碍的三种关系：铺在安全道上引导走位、摆在跳跃轨迹上方鼓励起跳、沿 S 形路线串联。
波次之间会根据上一波的动作留出恢复时间：跳跃有 0.8 秒硬直，因此"跳跃波 → 下蹲波"的间隔被强制拉长到至少 1.05 秒。

实测（机器人以固定策略游玩，每档 5 局、每局 150 秒，`density 0.58`）：

| 难度 | 死亡 | 障碍数 | 距离 | 得分 |
| --- | --- | --- | --- | --- |
| 简单 | 0 / 5 | 45 | 2808 米 | 约 730 |
| 普通 | 0 / 5 | 78 | 3510 米 | 约 1010 |
| 困难 | 0 / 5 | 114 | 4387 米 | 约 1300 |

## 运动结算（体态模式）

游戏结束时，体态模式的结算页会额外显示本轮运动数据：

| 项目 | 说明 |
| --- | --- |
| 起跳 | 实际起跳次数，一次跳跃只计一次，空中不会重复计数 |
| 下蹲 | 蹲下的次数，保持下蹲不重复计数 |
| 张臂 | 双臂水平张开的次数 |
| 举手 | 双手举起的次数 |
| 热量 | 动作总次数 × 0.2 千卡，系数见 `GameConfig.calories_per_action` |

只统计真正的奔跑阶段：3 秒倒计时、说明页、安全练习、暂停与失去追踪期间的动作都不计入。
统计基于六字段控制接口的上升沿，因此键盘模式与体态模式共用同一套计数逻辑；结算页只在体态模式显示这一栏（按键不算热量）。
主菜单标题为艺术字"一起运动吧"，窗口标题同名。

## 体态预览

体态模式的预览画面由视觉模块绘制：`CameraController.get_annotated_preview(width)` 返回已叠加骨架的镜像 RGB 小图，
骨架拓扑与可见度规则位于 `camera_control/pose_view.py`，与独立调试窗口共用同一份实现。
游戏端只负责在画面下方叠加一行实时读数：车道、追踪可信度、当前识别到的动作（跳跃 / 下蹲 / 张臂护盾 / 举手冲刺）。
追踪丢失时骨架会消失、读数转为红色提示。

## 代码结构

```text
game.py              启动入口（等同 parkour_game.main）
parkour_game.py      游戏循环、状态机、碰撞与计分、action() 动作分发
hud.py               全部界面：菜单、设置、说明、暂停、结算、游戏内 HUD
camera_preview.py    把摄像头帧转成 Pygame Surface（不依赖 OpenCV）
input_adapter.py     选择键盘或体态控制器，二者接口一致
player.py / entities.py / game_config.py / audio.py
level.py             关卡波次模式与生成节奏
rendering/           像素渲染器与粒子效果
```
